# 开发维护计划

本文件是已实现规则版的维护计划。原始 2026-10-31 实施计划的完整阅读与来源记录见 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)。原计划 Library ID 为 `libfile_445013c9c2948191b7af7149d2709417`；此文件不冒充其原始字节副本。

完整产品愿景、演进与待决事项另见 [design/GAME_VISION.md](design/GAME_VISION.md)，证据见 [design/SOURCES.md](design/SOURCES.md)。以下已交付基线、后续顺序与验收约束面向当前规则演习；不要将其“无永久损失”等约束推广成整个长期游戏的定案。愿景归档不自动扩大本轮实现或部署范围。

## 已交付基线

- P0：独立 Python API、SQLite、移动网页、锁定依赖、OpenAPI。
- P1：确定性规则内核、同时结算、守桥场景、固定种子 fixture。
- P2：通信队列、下属观察与玩家视角隔离、命令/回执、幂等推进及恢复。
- P4 规则版：战后事实对照、记录决策重放、有来源的合作记忆审阅与停用。
- P5 云端部分：32 项自动测试、手机/桌面浏览器全流程、备份恢复与源码运行包。

## 后续顺序

1. 先进行 3–5 人试玩，按 PLAYTEST.md 收集介入动机、看不懂的报告和是否愿意再开一局。根据反馈改核心循环。
2. 用户确认供应商、模型、每局预算和可接受延迟后，再实现 P3：兼容模型适配器、结构化提案、受限重试、超时提示、原子预算预留和用量结算。禁止借用其他项目密钥。
3. 对比相同场景下规则与模型的决策和汇报。测试非法输出、超时、费用不明、预算耗尽、观察泄漏和提示注入。供应商调用不在 SQLite 写事务内。
4. 扩展记忆前先保留来源与审阅机制。只取角色实际可知的信息，不能自动把全知复盘注入角色。没有永久兵力/装备增益。
5. NUC 连接和部署获确认后，按 DEPLOYMENT.md 在独立目录、独立数据库与端口完成内网真机验收。任何公网、隧道或网络规则改动另行确认。

## 每次修改的验收约束

- 真相只由规则结算改变；Agent 只提交经验证的提案。
- 普通游戏接口不得返回未送达报告或隐藏真相。
- 同一幂等请求最多一次逻辑提交；进程停止不补算现实时间。
- 重放使用已记录的决策，核对事件与状态摘要。规则变更明确提升版本，不静默更新 golden fixture。
- 运行数据库、密钥、环境文件、虚拟环境和临时包不能进入 Git。
- 提交前运行相关测试，记录 PASS/FAIL/NOT RUN；不得把云端浏览器模拟写成 NUC 真机验收。
