# 运行包与部署交接

本次只提供源码运行包和云端测试。以下 NUC 内容是未来操作说明，**本次未执行**。

## 云端本地开发

- Python 3.12，安装 `requirements.lock`；`bash scripts/run.sh`。
- 独立端口 8765、独立数据 `data/battle.sqlite3`；默认只绑定 127.0.0.1。
- 没有 systemd、Docker daemon、现有代理、隧道或服务改动。测试服务器可 Ctrl+C 停止。
- 端口冲突时 uvicorn 应明确退出，选择另一个 `BATTLE_PORT`，不要终止未知服务。

## 将来在 NUC 的操作顺序

1. 得到 NUC 可用连接与部署授权后，只读确认 Python、CPU 架构、磁盘、内存和现有端口。
2. 将该版本源码包放入独立游戏目录，独立 virtualenv 和数据目录；不复用 MyAgent 数据库、环境文件或发布通道。
3. 安装锁定依赖，按 README 先回环启动、运行 `/healthz`、`/readyz` 和无模型测试。
4. 用户确定内网访问方式后，选择明确的 LAN 地址绑定，而非默认开放所有接口。当前脚本不提供公网绑定开关。需要代理/VPN/隧道/防火墙更改时另行确认。
5. 手机真机完成下令、失联、刷新、复盘与第二局；关闭进程再启动确认存档。该项云端设备模拟不能替代。
6. 用 `scripts/backup.py` 做在线备份，确认备份可在独立数据库路径打开。按实际测量决定日志轮转和资源限制。
7. 若需常驻服务，再独立审阅 systemd 或容器配置；本包不安装系统服务。

## 回滚

升级前保留旧应用产物和 SQLite backup 文件。旧规则存档需要旧内核进行确定性再模拟。回滚先停止本游戏进程，切回旧应用，将备份复制到新的运行数据路径，设置 `BATTLE_DB`，再启动。确认 health/ready、存档版本与一次 replay 验证。不要在现有数据库上强行倒退 schema，也不要删除旧数据。

## 持久性

代码目录属于当前云工作区，保存寿命由平台决定。推荐保留交付的源码 ZIP。运行数据库默认在项目 `data/` 内，明确不包含在源码 ZIP 中；真实试玩产生存档后需要另行备份。不要把“Library 中有源码包”理解成“运行服务或存档已永久托管”。
