## 第 1 页 / 战报之外完整产品方案

异步 AI 军事组织成长游戏 / 朋友讨论版

### 先从一小群人开始

玩家从约 15 人的小团伙起步，逐渐形成更大的军事组织。你设计建制、挑选和培养下属、分配模型、下达意图；部队会判断、误解、协作，也会害怕和撤退。

### 指挥的是组织而非棋子

你认识战场的主要渠道是下属的汇报，而非客观全景。信息在观察、压缩、转述和执行中改变。部队在你离线时继续运转，战役结束后才揭晓完整事实。

### 想先把它做给谁玩

这是一个业余独立项目：先让自己和朋友玩得开心，再尝试向军迷推广，并探索平台模型服务的收入空间。它不是已有产品，没有完成玩法、成本或市场验证。

### 如何阅读这份方案

“已明确”指创作者确认的方向，不等于功能已实现；“建议”是可验证的机制候选；“待定”需要进一步选择。名称暂定，题材仍是一、二战前后。本文整合 2026 年 10 月 31 日讨论与最新语音修订。

## 第 2 页 / 从十五个人到一个组织

已明确 / 起家过程与两条成长线

### 共同经历是起点

约 15 人构成起家的共同历史。有人勇敢，有人谨慎，有人只是可靠的普通士兵；一起完成任务、面对损失，逐渐积累关系和组织习惯。具体起始人数与最小模拟单位仍待定。

### 两条成长同时发生

一条是现实的兵力、装备、补给与训练；另一条是 Agent 的自主判断、互相配合和授权默契。规模变大不代表更善于作战，模型变强也不代表组织已经磨合好。默契不是单向服从值。

### 规模不是固定终点

营团级是早先讨论的核心作战尺度，但不是唯一规模或永恒上限。由小团队成长、再面对更大组织的治理，是长期愿景；跨级成长如何落地、初版在哪一段停下，需要原型决定。

### 一段可能的玩家经历

你最早信任的伙伴成为军官，也可能一直留在基层。新人可以进入直属队伍，老伙伴可以被调到别人麾下。关系与历史继续存在，岗位却会随着组织需要而改变。此段为虚构体验示例，不是固定剧情。

## 第 3 页 / 组织由负荷推动演化

已明确 / 建制自由与制度涌现

### 从亲自安排到逐步授权

小队时期，你能逐一交代事情。人数、战线和任务增加后，汇报积压、资源争夺、响应变慢，下属开始请求协调。玩家才有理由建立分工、参谋、层级和制度，而不是到某等级自动解锁一种编制。

### 玩家设计指挥关系

谁指挥谁、谁向谁汇报、火力集中还是下放、哪些事必须请示，都属于组织设计。制度应改变实际负荷、协作和信息传递，不能只是一组菜单加成。

### 可以越级下达具体命令

玩家能够直接找基层单位做事，不强制只能沿层级下令。但越级可能带来重复任务、上级不知情或优先级冲突。后果来自真实任务与信息关系，不应只是固定扣分。具体回执与协调机制待定。

### 原始成员不是永久直属席位

亲信、朋友和正式指挥岗位需要分开。老伙伴可以留作士兵或成为别人的下属；玩家也可把新人放到关键岗位。成长不意味着所有初始成员必然晋升，也不意味着他们免于真实战役的损失。

## 第 4 页 / 部队有素质也有求生本能

已明确 / 模型角色与开场配额

### 每个单位有自己的模型角色

模型参与理解、计划、汇报与执行判断。系统注入怕死、服从、恐惧与溃散等约束，让下属不是可以随意抹掉个性的工具。“单位”最低到单兵还是班排，以及调用粒度和频率，仍需确定。

### 不能全军都是精锐

开场按配额搭配精锐、普通与更容易动摇的部队。精锐使用更好的系统提示词设定，普通部队执行较弱，易动摇部队需要支援与合适任务。具体比例尚未定，精锐也不会永不恐惧。

### 部队素质不同于底层模型

模型能力和费用是一条轴，系统赋予的角色质量与心理约束是另一条。昂贵模型不能直接删除恐惧和派系设定。建议由规则层保障关键配额和权限，避免仅靠提示词就能被自带模型绕过。

### 组织里还可能各怀心思

军官可以有不同忠诚、派系、保存实力或争功动机。历史风格剧本可参考具体时期的组织关系，但不能把某个阵营的所有人写成同一种性格；史实与架空动机要分别标注。

## 第 5 页 / 战争迷雾来自人的汇报

已明确 / 信息边界与通信损耗

### 你看到的是被理解过的战场

单位只能根据自身观察、收到的报告和既有记忆判断。玩家连己方的真实情况也未必知道：汇报可能落后、误认或被修饰。客观世界状态应独立存在，不能由模型临时编出来。

### 层层转述会改变重点

同一句“尽量保存兵力，天亮前守住桥”，可能被转成“危险时允许后撤”，再变成“必要时退到第二防线”。Agent Team 的关注点、上下文与压缩过程，会自然产生信息偏差。

### 通信本身也有世界规则

距离、设备、传令时间和通信破坏决定消息何时到达。模型的信息偏差与这些物理规则应区分，不把所有故障都解释成“熵增”。通信静默或被破坏，是下属自主判断的重要情境。

### 建议保留可追溯的证据

界面给出报告来源、发送与收到时间、转述链及相互矛盾的消息；可信度不能伪装成客观真相。命令与事件在发生时留存，战后才能对比真实事实、当时信息和实际行动。

## 第 6 页 / 战场指挥与战报原型

概念界面 / 所有数值与场景均为虚构示意

### 界面文字与结构

- 顶部标题：河谷战役 / 第 3 天。
- 视角标签：战时视角。
- 权限说明：指挥权限：营部 / 当前信息来自下属汇报。
- 地图标记：一连、二连、桥头；河流与桥梁示意。
- 敌情标记：疑似装甲；侦察报告 12:10。
- 地图说明：阵地与敌情均为报告位置，非实时真值。
- 战报区标题：收到的战报。
- 入口：查看原始报文。
- 战报 1：12:20，二连请求反坦克支援。村西疑似装甲集结，数量待核实。
- 战报 2：12:12，一连阵地稳定。报告发送于 10:05；新消息尚未收到。
- 输入区标题：新的任务意图。
- 输入示例：守住桥梁，优先核实侧翼。无法坚持时允许退至第二防线，并报告位置。
- 操作按钮：向一连越级下令；提交给营部。

界面表达：报告保留时间和来源；地图不是全知状态。玩家可沿层级或越级下令，系统不能默默替玩家消除冲突。界面、动作入口和示例文字均为候选。

## 第 7 页 / 战后才看见另一半战场

虚构场景 / 从命令到客观复盘

### 命令与当时的判断

你要求守住桥梁并避免无谓伤亡。营部报告“村西发现装甲集结，一连阵地稳定”，你把反坦克支援调往西侧。这个决定可能在你当时掌握的信息下合理。

### 实际发生的情况

侦察兵把一辆卡车当成第二辆坦克，营部转述时放大了威胁。“阵地稳定”是旧报告；一连已经发现侧翼威胁并后撤，新电报尚未送到。正面此时失去火力支持。

### 复盘需要同时展示五件事

客观事件、各单位实际观察、报文与转述、你的命令和下属行动、战略目标结果。玩家据此分辨问题来自部署、条令、情报、沟通还是个体选择，而不是只看谁赢了。

### 解释不能替代证据

模型战后说出的理由只能作为角色叙述，不能当作它当时内部推理的证明。复盘以留存的事件、输入、命令和行动为依据。建议允许先重看当时视角，再揭开全局，以保留戏剧性与学习价值。

## 第 8 页 / 异步不等于无人负责

已明确 / 多日节奏与自主执行

### 有空介入也可以不介入

战役可以持续几天或几周。你看战报、调整目标，或信任下属继续执行。组织能够独立运转本身就是成长成果，不能把玩家几天不上线自动判为恶意挂机。

### 自主来自目标与磨合

没有新命令，单位仍按已有目标、授权、所知信息和角色约束行动。通信静默或被破坏时，老练组织可能做出更连贯的决定；没有磨合的组织可能各自为战。自主不等于绝对服从或保证正确。

### 建议把技术故障说清楚

模型超时、费用耗尽、命令未提交，应作为可靠系统状态提示，不能伪装成角色抗命。预算上限、调用失败时继续旧计划或保守行动，都是待验证的保护机制。

### 仍要证明节奏真的轻松

通知哪些事、夜间如何推进、频繁在线是否占优，都未定。建议先观察玩家能否离线后快速理解局势，避免短窗口迫使玩家常驻。允许自主，并不意味着必须让玩家承担无法理解的随机惩罚。

## 第 9 页 / 演习与长期战役分工

已明确 / 同一批 Agent 的两种使用方式

### 友谊演习用于一起玩

玩家带上自己培养的 Agent 与朋友约战。可以调整规模、拉平条件，将军也能回来带小队。不为了公平强制换成全新 Agent；具体缩放、模型限制和约战规则由房间方案继续确定。

### 演习保留经验但不毁掉家底

保留明确标记为演习的记忆与磨合，不产生永久阵亡、被俘或兵力装备损失，也不发放长期兵力装备奖励。演习有关系与协作收益，不能写成完全没有成长或完全没有代价的系统。

### 长期天梯承载真实成长与损失

匹配旗鼓相当的对手，承载部队的真实发展和战役后果。可能阵亡、被俘，甚至建制覆灭；不能把它写成另一种无损竞技。匹配考虑哪些维度、如何衡量实力，算法尚未定。

### 两种模式仍有边界问题

演习记忆如何进入真实战役、规模拉平后保留哪些能力、长期战役失败后如何继续，都需要验证。真实损失不是已经解决挂机套利的证明，演习磨合也可能带来刷训练的风险。

## 第 11 页 / 培养的是有共同历史的伙伴

已明确 / 自养 Agent 上场与关系延续

### 不能把自己养的 Agent 留在场外

玩家投入命令、训练和共同经历形成的伙伴，必须能进入对抗。更换岗位或对局规模，不应抹去已有关系。友谊演习允许高阶军官承担小队任务，以适应朋友之间不同成长阶段。

### 成长需要表现在行为上

训练、共同作战与演习，可以让 Agent 更理解彼此的表达、授权和配合方式。这里的“成长”不预设必须微调底层模型；采用记忆、条令、案例或其他方法，尚待技术与玩法验证。

### 可以亲近但不必一直直属

一个最初的战友可以继续当普通士兵、调往别人的部队，也可以走向指挥岗位。玩家关系网与正式组织图不同，允许感情延续，也允许任人唯贤或面临用人取舍。

### 真实损失让共同历史有分量

真实战役里，重要伙伴也可能阵亡或被俘，组织可能失去关键人员。记忆如何保存、被俘如何处理、建制覆灭后的继续方式，尚无定案；不能擅自承诺永久复活、保险或无损回滚。

## 第 12 页 / 军官组织与调任原型

概念界面 / 关系与岗位分开，允许越级命令

### 界面文字与结构

- 顶部标题：部队组织 / 人员调任。
- 标签：概念编制。
- 总说明：正式岗位与亲近关系，是两张不同的图。
- 组织图根节点：你 / 当前组织指挥者。
- 根节点直属下级一：一队 / 周禾。
- 根节点直属下级二：二队 / 陈砺。
- 人物卡片：李川 / 起始伙伴之一。
- 当前岗位：一队普通士兵。
- 共同经历：河谷撤离 / 首次友谊演习。
- 关系说明：关系保留，不等于永久直属或必然晋升。
- 拟调任：二队 / 通信联络岗位。
- 候选提示：一队当前任务仍依赖此成员。调任可能产生交接负荷；是否同时通知两位队长，由玩家确认。
- 操作按钮：查看当前任务；确认调任。
- 辅助说明：也可以直接下达具体命令，后果由任务关系产生。

示例姓名、职务和编制均为虚构。调任与越级指挥允许存在，不用硬性禁令替代组织后果；具体信息同步、提示与确认流程待验证。

## 第 13 页 / 战役内容与军迷扩展

已明确 / 自由设定、历史灵感与非对称目标

### 资源可以配平也可以参考历史

自由战役给双方大体配平的资源，由玩家设计建制。历史或假设战役参照具体力量与条件，不保证双方兵力相同。目标可以是夺桥、拖延、掩护撤离或保存力量，胜负按各自目标判断。

### 仍是一二战前后的题材方向

从小团伙起家、逐渐治理大组织，是成长与治理的类比，并不意味着改成古代战争背景。具体国家、年份、默认战场及史料范围尚未确定。

### 让军事幻想能够被扩展

希望军迷制作编制、装备、地图、军官设定、阵营关系、战役目标和规则，把“如果由我来指挥”变成与朋友的对局。历史考据与架空设定应当有区分，不用性别或专业门槛排除玩家。

### 扩展平台不是初版前提

编辑格式、分享、兼容、审核和是否允许代码扩展都待定。建议先用一个可控场景验证玩法，再抽出有用的内容接口；不先建设完整军史数据库或创作交易市场。

## 第 14 页 / 模型军费与商业方向

已明确 / 自带调用额度与平台付费模型

### 模型差异本来就是对抗内容

玩家可以使用自己的 API 配置和 token 额度，也可以购买平台提供的模型服务。贵模型与便宜模型可以同场，通过组织、条令和配置取胜；“我的模型更便宜却赢了”是刻意保留的乐趣。

### 军事资源与真钱分开

兵力、装备和补给是游戏资源；模型调用是实际费用；平台还可能有服务成本。不能用同一个数值混淆三者。精锐质量配额依然存在，购买贵模型不等于购买无视角色约束的部队。

### 平台售卖的是便捷服务

平台模式减少接入和管理门槛，是潜在收入来源，不承诺获胜。定价、付费方式、供应商与授权条款尚未定。费用上限、消耗展示和密钥保护应在收费前验证，不能靠无意义对话制造消耗。

### 先测成本再谈盈利

需要测量各规模、时长、模型组合的有效决策与总调用量，包括重试、上下文和持续运行成本。朋友自用价值先于商业证明；毛利、市场规模、留存和收入都还没有证据。

## 第 15 页 / 长期战役怎样持续有趣

朋友反馈引出的风险 / 以下机制均为候选

### 担忧不应被宣传掩盖

朋友提出即时激励和内容多样性的疑问，例如是否玩一周就腻。这是值得验证的风险假设，不是已经测得的留存结论。战役长，不等于体验一定丰富。

### 候选一：让短期决策有可感知后果

在大目标下安排阶段任务，提供值得介入的战报、下属求助和局部成果。反馈可以来自任务推进与人物关系，而不必每次上线都发兵力奖励。频率过高反而会变成工作。

### 候选二：用组织问题产生变化

不同地形、目标、通信条件、军官组合和资源压力，让同一支部队面对不同难题。变化应该让玩家重新判断，而不是给已有敌人加数值；也不能依赖无穷随机文本填充内容。

### 候选三：允许低风险的短体验

友谊演习提供较短、可约定规模的对抗，长线战役负责持续成长与损失。分享有因果的战后故事，可能增加围观和讨论。建议用实际重复参与来筛选机制，而不是把所有候选一次塞进初版。

## 第 16 页 / 世界规则与 Agent 分工

建议 / 可靠游戏底座支撑不可靠角色

### 客观世界独立结算

位置、时间、地形、弹药、装备、伤亡与行动合法性由游戏规则维护。模型负责解释信息、判断、计划、请求和汇报，不可以凭一段输出创造战果或看到隐藏敌军。

### 信息与权限必须硬隔离

每个角色只获得授权范围内的观察和消息。玩家可以越级命令，但不能因此读到全知状态。自带模型端点可能不遵守提示，关键配额、权限和动作校验应放在可信服务器，而非只写在系统提示里。

### 事件驱动而非无休止聊天

每单位有独立角色与信息，不等于每秒调用一次。可考虑按遭遇、命令、通信变化等事件触发，其他时间由稳定计划和规则执行。具体调度、上下文和记忆机制待测，不能承诺低成本。

### 技术状态必须透明

命令是否提交、任务队列、模型失败和预算要可靠可见。保存事实事件、消息、行动及版本供复盘；演习记忆带标记，避免污染角色对真实伤亡与资源的认知。隐私和密钥不进入战报或公开日志。

## 第 17 页 / 风险与验证方式

待验证 / 不是完整研发前的形式检查

### 角色有缺点但玩家仍有作用

需要看到玩家能通过组织、条令、授权和支援改变结果，能解释一部分失败，并愿意再次尝试。若只感到 AI 乱来，应调整信息反馈与角色约束，而不是增加随机失误。

### 成长不能只是数字或文本

需要看到同一批 Agent 在新情境下表现出可辨认的协作变化，同时保留差异和犯错可能。不能凭自述“我学会了”证明学习，也不能用永久顺从取代默契。

### 长线与演习可能被利用

真实损失、挂机、自主运行、训练收益和跨模式记忆的组合需要专门测试。让自然离线合法，同时识别资源或训练漏洞。不能在尚无规则与对局证据时宣称套利已经解决。

### 规模与现金投入要可承受

比较不同 Agent 数量、通信层级和时长下的费用、延迟与故障。验证预算保护、数据边界和自带端点约束。对业余项目，维护成本与持续投入意愿同样影响能否继续。

## 第 18 页 / 初版边界与讨论问题

建议的验证顺序 / 不承诺工期或上线日期

### 先证明一段完整体验

建议从小规模组织、一个虚构场景、有限动作和可追溯战报开始：能建制、下令、自主行动、发生可理解偏差、结算并复盘。演习先验证朋友同玩的乐趣，再逐步验证持续成长与真实损失。顺序仍待创作者选择。

### 长期愿景分阶段兑现

保留自养 Agent 上场、两条成长线与自然组织演化的方向；不要一次承诺跨级成长、完整天梯、全套史库、所有模型、正式售卖和模组市场。技术、平台、预算、投入时间与团队协助尚未确定。

### 请朋友帮忙判断

你最想体验的是带熟悉的伙伴成长，还是临场指挥与复盘？能接受怎样的真实损失？每天愿意看几次战报？演习与长期战役各有什么吸引力？什么会让你玩一周后不再回来？

### 下一步的判断标准

希望得到真实体验后的反馈，而不只是“挺有意思”。先判断朋友是否愿意再玩、玩家是否能学到并活用组织经验、创作者是否负担得起，再决定开发深度与商业探索。当前所有页面和原型均为方案，不是可玩产品。
