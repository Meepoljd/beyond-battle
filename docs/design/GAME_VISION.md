# 《战报之外》完整游戏设计愿景

归档日期：2026-11-04。本文记录设计方向、演进与未决问题，不新增玩法决定，也不将尚未实现的愿景当成功能清单。当前仓库是守桥演习 Demo；完整游戏愿景不能由该切片的限制反向定义。

阅读顺序：[证据与来源](SOURCES.md) → [用户原话及助手记录](source-notes/2026-10-31-conversation.md) → [18 页方案转录](source-notes/2026-10-31-product-plan-transcript.md)。下文 P 为用户原话，S 为助手二级记录，D1 为完整方案转录，D2 为 Demo 实施计划，A 为助手建议索引。证据支持“提出了什么”，不自动证明可实现、有效或已被用户最终确认。

## 1. 愿景与项目动机

综合 P1–P11、P16–P19、P24–P28：这是一款以一战、二战前后为初始军事想象背景、以营团级指挥为已选择切入尺度的异步军事组织游戏。玩家从建制、军官、模型配置和授权关系开始经营一支会判断、误解、协作、恐惧和撤退的军队，主要凭主观战报下达目标与介入，在对抗和长期成长中形成自己的部队历史，战后再看见客观事实。这是综合归纳，不是一条用户逐字定义。

用户明确把它定位为业余独立项目：第一目标是自己和朋友玩得开心，第二目标才是推广与个人独立开发的试探，尽可能兼顾。先展示概念取得朋友反馈，再做立项讨论、策划和 Demo。商业可能性可以探索；询问能否融资不代表已经决定创业或融资。[P8、P18–P20]

早期称为 RTS，随后的直接原话选择了天或周维度的轻松异步战役，不能用 RTS 一词强加持续在线操作。营团级是明确纠正“银团”后的选择；从更小部队起家到更大组织是后续探索，具体路径和终点未锁定。[P1、P6、P15–P17、P26–P27；D1 第 2、13 页]

## 2. 用户直接表达的方向与问题

| 主题 | 原话支持的内容 | 未被这些原话确定的内容 |
|---|---|---|
| 指挥与执行的落差 | 单位由大模型参与执行；理解偏差和执行失误可以成为真实感与乐趣 | 单位最低粒度、每名士兵是否独立调用、频率、可靠性下限 [P1] |
| 主观认知 | 玩家信息也来自模型汇报，客观事实在后面复盘 | 具体 UI、回放顺序、五层证据界面；这些是方案展开 [P2；D1 第 5–7 页] |
| 战前建制 | 从部队建制开始让玩家设计；可大体配平，也可使用历史力量和战略目标 | 不限定完全对称竞技、只以歼灭判胜，也未锁定营长或团级战斗群身份 [P5、P15–P17] |
| 轻松异步 | 随时看报与下令，也可以不下令；一场可持续天或周 | 现实/战役时钟、暂停、夜间、通知与高频在线优势如何约束 [P6] |
| 通信偏差 | 借 Agent Team 的“熵增”模拟多级信息损耗 | 不能把任意程序故障或无因果的模型错误都归为已认可机制 [P7] |
| 心理与部队质量 | 注入怕死、溃散等提示词；精锐与普通等按配额分配，不能全军精锐 | 配额数字、精锐永不害怕、固定三级命名；P10 尾句有歧义 [P4、P10] |
| 组织私心 | 以国民党部队举例，追求“各怀鬼胎”的组织感觉 | 所有历史阵营/个体一律某种性格；派系、争功等具体维度是建议 [P11] |
| 模型军费 | 自带 token 可模拟练兵成本，是对抗资源；廉价模型赢贵模型有额外乐趣 | 强制所有比赛使用同模型、现实花费已经配平 [P1、P3] |
| 商业入口 | 同时考虑自带 token 和平台售卖模型服务 | 模型名单、供应商、价格、抽成、支付、单局预算和服务承诺 [P9] |
| 军迷扩展 | 支持军迷扩展，满足军事幻想 | 未批准首版编辑器/API范围，也不是玩家性别准入限制 [P9] |
| 长期亲信 | 用户主动提出用 Agent 记忆建立熟悉伙伴、合作模式与授权关系 | P24 是探索式提问；记忆架构、战力增益、亲信与权限关系未定 [P24] |
| 朋友与新人 | 成长的规模代差影响朋友同场；每战役需要规模约束；新人面对技巧差距可能难融入 | 没有已验证的规模缩放、匹配或新手保护算法 [P25、P27–P28] |

“以男人的军事幻想为目标”保留在 P9 原文；本文将其解释为军事指挥、建军和组织成长的体验与创作空间，不增设排他性的玩家性别条件。D1 第 13 页也明确不以性别或专业门槛排除玩家。

模型能力/费用与系统赋予的部队质量/心理约束分成两条轴，是助手和 D1 第 4 页的设计展开；直接原话支持二者都要形成差异，但没有逐条确认这个具体架构。P10 的“以及算是怂的”保留原样，不擅自修成精确的第三类定义。

## 3. 长期成长：用户探索与通话二级整理

### 3.1 从共同经历到更大组织

用户探索带一批人参战、成长后扩大规模，再进行同级别对抗；举例从带队守桥，逐渐进入营团乃至国家级对抗。这些“那如果”“比如说”不等于首版要做国家经营。[P26–P27]

S1 当时的语音工作稿把它整理为类似“刘邦式起家”的关系与治理体验，并记录两条成长线：部队的规模、军备、训练，以及 Agent 的自主判断、与玩家的默契、组织内部协作。D1 第 1–3 页沿用这些方向。它们应保留为二级整理/历史方案的表述，不能冒充尚未取得的通话逐字原文。起家的类比没有把战争题材改成古代。[S1；D1 第 13 页]

“约十五人”是 S1/D1 的例子；D1 第 2 页明确起始人数和最小模拟单位仍待定。它不等于 Demo 中每支部队默认十五人的产品硬约束。[D2 第 0.2 节]

### 3.2 关系、岗位、指挥关系分开

S1 记录：初始伙伴可能适合做士兵而不适合做指挥官；共同历史、当前岗位和指挥关系应分开。老伙伴可调入其他部队保留经历，新人才可以进入直属班子，退出直属不等于退出故事。D1 第 3、11–12 页进一步表达任人唯贤和用人取舍，示例中的李川、周禾、陈砺、岗位与组织图均为虚构，不是固定剧情或必备角色。

不预设所有初始成员必然晋升、不预设亲信自动扩大权限，也不预设微调底层模型才算成长。记忆、条令、案例等方案仍需验证；成长需要表现为可辨认的行为变化，不能靠角色自述“我学会了”或永久顺从证明。[S1；D1 第 11、17 页；A1–A6（父会话综合摘要）]

### 3.3 管理负荷推动组织演化

S1 记录的当时焦点是：规模增加 → 老伙伴的人数与事务增加 → 超过管理能力 → 请求帮助或单位表现下降 → 玩家判断调整。资源分配问题、越来越忙、单位性能下降是记录中的主要信号。请示积压、命令不一致、训练疏漏、求助或硬撑是当时的候选表现；减负、副手、自组班子、晋升或调任尚未成为完整规则。

制度建设应随压力自然出现，而不是用“现在进入制度建设阶段”的显式解锁点替代发现问题与取舍。这是 S1 所记录的方向，D1 第 3 页再次表达；归档不把它提升为已取得逐字确认的用户原话，也不把当时暂缓经济/国家级/反挂机讨论理解为永久删除这些愿景。

### 3.4 越级与自主

S1 记录不希望以硬规则禁止玩家向前线个人或单位细致下令；D1 第 3、6、12 页保留沿层级或越级的入口。命令冲突、上级不知情、等待玩家拍板等是自然后果候选，不等于固定扣“越级惩罚分”，具体同步和确认机制仍待定。

S1/D1 希望组织可以自行行动几天，静默或通信受损时依原目标、授权、所知信息和心理约束判断，恢复后再汇报。自主不保证正确，也不把正常离线判成恶意挂机。[P6；S1；D1 第 8 页]

## 4. 两种模式与真实后果

下表主要依据 D1 第 9–11 页，其原文自标“已明确”。目前缺少对应逐条用户原话；故保留为**历史完整方案明确记录的方向**，不冒充 P 类证据，也不表示这些模式已实现。

| 方面 | 友谊演习（D1 方案） | 长期战役/天梯（D1 方案） |
|---|---|---|
| 目的 | 与朋友一起玩，适配成长阶段差异 | 长期组织成长、真实战役后果 |
| 参演伙伴 | 带自己培养的 Agent，不为公平强制换陌生角色；高级军官可以回来带小队 | 保留长期投入的人员、组织与历史 |
| 条件 | 双方约定规模与条件；缩放、模型限制尚未定 | 旗鼓相当的对抗；实力维度与匹配算法未定 |
| 损失 | 无永久阵亡、被俘、兵力装备损失 | 可能阵亡、被俘、建制覆灭；延续方式未定 |
| 保留与奖励 | 标记为演习的记忆和磨合；不发长期兵力/装备奖励 | 承载真实发展与损失，经济和奖励规则尚未定 |
| 未解决风险 | 记忆/磨合的刷训练收益、跨模式影响 | 廉价部队套利、正常自主离线与恶意挂机的区分 |

用户直接提出的规模上限、朋友同水位、新人融入问题仍是设计约束；上表是当时的一种收敛方案，不能宣称已经解决这些问题。[P25–P28] 对永久损失的讨论还可追溯到 S1，但不能用损失的存在证明反挂机已解决，也不能擅自承诺永久复活、保险或无损回滚。[S1；D1 第 11、17 页]

## 5. 军事题材、内容扩展与经济

用户允许大体配平资源，也允许按历史力量展开不对称对抗，围绕真实或模拟战略目标而非只看歼灭。[P5] D1 第 13 页列出夺桥、拖延、掩护撤离、保存力量等例子；具体国家、年份、默认战场、史料范围仍未定。

军迷扩展是用户方向。[P9] 编制、装备、地图、军官、阵营关系、目标和规则，是 D1 第 13 页的展开；格式、分享、兼容、审核、是否允许代码扩展都待定。先验证一个可控场景再抽出接口是建议，不意味着已批准完整军史数据库、交易市场或所有模组。

自带 API/token 与购买平台模型服务是用户明确希望兼顾的入口。[P1、P3、P9] D1 第 14 页进一步建议把游戏兵力装备资源、现实调用费用、平台服务成本区分；平台提供便捷服务而非胜率承诺。预算上限、用量显示、密钥保护、供应商授权、定价和付款方式仍需设计。模型便宜获胜的快感应保留，不能悄悄改写成所有比赛强制同模型；也不能声称真实成本已被配平或利润已有证据。

## 6. 反馈、代入、社交与新人的问题

P22 是用户转述朋友对即时激励不足和模式单调的反馈。朋友说“一个礼拜左右就会腻掉”是风险判断，不是留存数据；竞技和内政是朋友建议，不等于用户批准国家经济、每日任务或全套内政。P23 继续追问无预设剧情时怎样产生代入与激励。

以下是助手/D1 的**候选方案，待验证而非已定需求**：

- 让问题、选择和组织反应形成短反馈，再叠加阶段成果与最终真相；不以每次上线发资源奖励代替意义。[A1–A6（父会话综合摘要）；D1 第 15 页]
- 用地形、任务、通信、军官组合和资源压力创造需要重新判断的变化，不用无限随机文本和敌人数值膨胀填充内容。[D1 第 15 页]
- 较短、规模可约定的友谊演习和有因果的战后故事可以促成重复参与；15–30 分钟只是测试假设，不是用户选定局长。[A1–A6（父会话综合摘要）；D1 第 15 页]
- 命令模板与分层战报帮助新人，同时保留自由表达；战前/战役间的任命、训练、整编、休整等比直接铺开国家建设更贴近当前主题。[A1–A6（父会话综合摘要）]
- 长期拥有的组织、某场规模上限与实际出场部队分开；朋友自由房、约定规模房、预设部队房、换边、合作或分级混战只是候选，尚未确定优先级。[A1–A6（父会话综合摘要）]
- 新人可以从预设部队、无永久损失演习或与朋友协作的独立任务进入，但不能把新人变成老玩家刷奖励的附属。[A1–A6（父会话综合摘要）]

P25–P28 中的资产/规模代差、技巧差距和朋友分流问题仍未解决。把公平进一步拆成资产、经验、默契和社交四类，是整理分析，不是用户已经规定的四项规则。

## 7. 世界规则与模型边界：建议和实现分开

D1 第 16 页明确以“建议”标注权威世界结算、信息与权限硬隔离、事件触发调用、技术状态透明。客观位置/弹药/伤亡由规则维护，模型在有限观察内理解、计划、请求、汇报；自带端点也不能绕过关键配额和权限。模型战后的解释不证明当时内部推理，复盘应依据发生时记录的事实、输入、命令与行动。[D1 第 7、16 页；A1–A6（父会话综合摘要）]

D2 将其中一部分细化为 Demo 实施约束，当前规则版也采用了有限视野、确定性结算、事件与决策记录。**技术底座已实现不代表单位自主大模型、长期成长和成本控制已被验证。** 软件错误应明确提示，不用剧情“抗命”掩盖超时、预算耗尽或未提交；供应商、预算、调度、回退等仍需验证。[D1 第 8、16–17 页；D2 第 2、4、7 节]

## 8. Demo 与长期愿景的范围对照

用户先提出 NUC Demo，再请求执行计划和开发实施计划，随后要求在云端开始实现“昨天说的游戏的 demo”。[P29–P32] 守桥方案来自 S2，D2 是建议实施基线；后续实施请求构成推进背景，不意味着所有默认值变成长期不可变需求。

| 维度 | 当前 Demo / D2 的验证切片 | 长期方向与仍待讨论之处 |
|---|---|---|
| 对局 | 单人对规则敌军 | 与朋友对抗、合作候选与长期同级对抗；多人规则未定 |
| 规模 | 默认 3 名军官、各 15 人的小部队 | 营团切入，微小团队起家及更大组织探索；人数与路径不固定 |
| 时间 | 默认 16 回合、每回合 5 分钟战场时间，手动推进 | 天/周级异步与多日自主；夜间、现实时间与通知未定 |
| Agent | 确定性规则提供者，真实模型接口尚待接入 | 角色有自主判断、理解偏差、恐惧、组织私心；调用粒度与心理机制未定 |
| 记忆 | 审阅带来源的少量沟通格式经历 | 亲信、授权默契与关系延续；方法、收益和盲点待验证 |
| 后果 | 本场伤亡/装备，不带永久损失或奖励 | 演习与真实战役分工；长期阵亡/被俘/覆灭的方向来自 S1/D1，细则待定 |
| 组织 | 允许越级命令，记录上级延迟同步 | 负荷驱动分工与制度、任免调任、关系图与组织图分离 |
| 内容与费用 | 单一可控守桥场景，无模型费用/支付 | 历史或虚构目标、军迷扩展、自带/平台模型服务；首批范围与预算待定 |

## 10. 待决事项与验证门槛

以下问题保留开放；没有原始依据时不填比例、人数、模型名单、价格、工期、胜负公式、技能树、匹配制度或国家经济系统。

1. 长期玩家是不断晋升的指挥官，还是持续扩张组织的领导者？营团是常用战役尺度还是成长阶段？[P15–P17、P26–P27]
2. 基层单位到单兵、班、排还是连？独立 Agent 的含义、同时活动数量、调用触发和频率是什么？[P1；D1 第 4、16 页]
3. 亲信记忆保存什么、谁知道什么、如何影响合作、权限和战力？演习记忆如何进入真实战役？[P24；D1 第 9、11、16 页]
4. 战役规模/投入上限、精锐比例、配平方式与历史不对称胜负如何规定？[P5、P10、P25]
5. 如何维持朋友同场、新人有意义的参与，避免成长把社交圈拆开？[P25–P28]
6. 永久损失、被俘、老伙伴调任或退场、组织覆灭后怎样继续？廉价部队和演习训练套利如何验证？[S1；D1 第 9、11、17 页]
7. 自主几天时如何处理通信、默认预案、通知、费用、夜间、暂停、时钟和时区？[P6–P7；S1；D1 第 8 页]
8. 具体权限、越级同步、任免、交接与治理后果如何自然出现？[S1；D1 第 3、12 页]
9. 训练、纪律、士气、派系和模型能力如何结合，哪些属于硬规则，哪些由模型表现？[P4、P10–P11；D1 第 4、16 页]
10. 先验证哪些短反馈与模式变化，怎样判断“想再玩一局”而不只获得概念认同？[P22–P23；D1 第 15、17–18 页]
11. 军迷扩展先开放何种数据/规则/工具，史实与架空、审核、兼容和版本如何管理？[P9；D1 第 13 页]
12. 平台定价、服务费、供应商授权、预算、密钥和联机防作弊怎样实现？融资不是当前必需条件。[P3、P9、P19–P20；D1 第 14、16–17 页]

D1 第 17–18 页和 D2 建议的共同验证原则是：玩家能通过组织与干预改变结果、能解释失败的一部分、同一批伙伴出现可辨认且非全能的协作变化、朋友愿意再次体验、成本与维护投入可承受。它们是待实测的门槛，不是归档完成后自动成立的结论。
